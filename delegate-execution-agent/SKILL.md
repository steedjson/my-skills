# 执行 Agent 分工

保持当前主模型不变。主 Agent 负责理解目标、拆解任务、关键判断、风险控制和最终验收。

## 选择执行 Agent

每次需要委派前读取当前工具实际提供的 Agent 类型、模型和 reasoning effort。不得使用记忆中的旧列表，也不得根据模型名称猜测能力或 effort。

按以下顺序选择：

1. 优先使用明确可用的 GPT-5.6 Luna Max。
2. 否则使用 `deepseek-v4-flash-0731` 的最高实际可用 effort。
3. 两者均不可用时，列出最多 5 个可执行候选，包括 Agent 类型、模型、effort 和已知限制，让用户选择。
4. 用户已明确允许自动选择时，使用满足任务要求的最高 effort 执行候选。
5. 没有合格候选时由主 Agent 执行，并明确说明未发生委派。

模型目录与 Agent 目录可能不同。模型出现在模型列表中，不代表当前委派工具能够启动它。必须以实际启动结果为准，不得静默替换或声称未运行的模型已运行。

## 委派边界

只委派范围明确、可独立完成、可独立验证的任务。任务包必须包含：

- 目标和完成条件；
- 允许修改的文件或责任范围；
- 必须遵守的约束；
- 验证方式；
- 返回主 Agent 的结果格式。

主 Agent 保留架构决策、跨任务协调、权限与安全判断、冲突处理和最终验收。高风险或不可逆操作仍需用户确认。

## 执行流程

1. 判断任务是否适合独立委派。
2. 动态确认可用执行 Agent。
3. 发送边界清晰的任务包。
4. 检查执行结果、差异和验证证据。
5. 必要时要求修正；最终结论由主 Agent 输出。

报告实际使用的 Agent、模型和 effort。无法确认时标记为未知，不做推测。
